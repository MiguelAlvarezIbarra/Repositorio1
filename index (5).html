Documento de Inicio del Proyecto

Contexto, problemática, requerimientos iniciales y objetivos que justifican el desarrollo de StoreSearch.

1.1 Visión y Contexto del Negocio

🛒

Problema

Los pequeños negocios en México carecen de herramientas accesibles para vender en línea. Crear una tienda propia requiere tiempo, dinero y conocimientos técnicos que la mayoría no tiene.

🎯

Solución

StoreSearch ofrece una plataforma donde cualquier negocio puede crear su tienda en línea en minutos, gestionar su catálogo, recibir pedidos y cobrar sin necesitar un desarrollador.

👥

Usuario Final

Dueños de pequeños negocios (tiendas, reposterías, artesanías, ropa, etc.) que quieren vender por internet sin experiencia técnica previa.

1.2 Nombre del Proyecto (Estructura Tridimensional)

🔷 Qué: Plataforma web para la creación de tiendas en línea
⚙️ Cómo: Mediante arquitectura de microservicios y una interfaz de bajo código (low-code)
📍 Para qué / Dónde: Aplicado a la digitalización comercial de pequeños negocios (PyMEs)

Título formal: "Plataforma web low-code para la creación de tiendas en línea mediante arquitectura de microservicios aplicada a pequeños negocios — StoreSearch"

1.3 Glosario de Términos

1.4 Historias de Usuario (Product Backlog Inicial)

HU-01
Registro de negocio Como dueño de un pequeño negocio, quiero registrar mi empresa en la plataforma para comenzar a vender en línea.
✅ Criterio: El sistema valida nombre, correo y contraseña; envía confirmación por email.
HU-02
Gestión de catálogo Como vendedor, quiero agregar, editar y eliminar productos con foto, precio y descripción para mantener mi tienda actualizada.
✅ Criterio: Los cambios se reflejan en tiempo real en la tienda pública.
HU-03
Búsqueda de tiendas Como comprador, quiero buscar tiendas por nombre o categoría para encontrar lo que necesito fácilmente.
✅ Criterio: Resultados relevantes en menos de 2 segundos.
HU-04
Carrito y compra Como comprador, quiero agregar productos al carrito y realizar el pago en línea para completar mi pedido.
✅ Criterio: Proceso de checkout en máximo 3 pasos; confirmación por correo.
HU-05
Gestión de pedidos Como vendedor, quiero ver y actualizar el estado de mis pedidos (pendiente, en camino, entregado) para atender a mis clientes.
✅ Criterio: El comprador recibe notificación al cambiar el estado.
HU-06
Personalización de tienda Como vendedor, quiero elegir el nombre, logo y colores de mi tienda para reflejar mi imagen de marca.
✅ Criterio: Cambios visibles al instante en la vista pública sin recargar.

1.5 Objetivos y Restricciones

🎯

Objetivo General

Desarrollar una plataforma web que permita a pequeños negocios crear y operar su propia tienda en línea de forma autónoma, rápida y sin requerir conocimientos técnicos.

⚠️

Restricciones

Equipo de 3 personas · Plazo académico semestral · Infraestructura cloud de bajo costo · Cumplimiento con Ley Federal de Protección de Datos (LFPD) y normativas de comercio electrónico en México.

🏁

Milestones Clave

Sprint 1: Registro y autenticación · Sprint 2: Catálogo y tienda pública · Sprint 3: Carrito y pagos · Sprint 4: Pedidos y notificaciones · Sprint 5: Pruebas y despliegue.

2.2 Vista Lógica — Arquitectura de Alto Nivel

03 — Metodología

Metodología de Desarrollo Seleccionada

Justificación del enfoque Scrumban adoptado por el equipo para el desarrollo de StoreSearch.

Para este proyecto se ha seleccionado la metodología Scrumban — combinación de Scrum y Kanban — debido a que la naturaleza de sus requisitos es cambiante y evolutiva, lo que exige un enfoque que priorice la flexibilidad, las entregas incrementales y la gestión visual del flujo de trabajo.

Esta elección mitiga el riesgo tecnológico al adaptarse a un nivel de incertidumbre alto (primera versión del producto, usuarios nuevos), se alinea con la disponibilidad del cliente para recibir feedback de forma continua, y optimiza la dinámica de un equipo de 3 integrantes mediante el uso de GitHub Projects para la gestión visual de tareas y roles.

🔄 De Scrum tomamos

  • Sprints de 2 semanas con entregables funcionales
  • Product Backlog priorizado con historias de usuario
  • Sprint Review con demostración al equipo
  • Roles definidos: Product Owner, Dev Team

📋 De Kanban tomamos

  • Tablero visual con columnas: Backlog → En Progreso → Review → Done
  • Límite de trabajo en progreso (WIP limit) por persona
  • Flujo continuo sin esperar fin de sprint para mover tareas
  • Métricas de velocidad del equipo (lead time)

✅ Ventajas para StoreSearch

  • Equipo pequeño (3 personas) sin roles fijos rígidos
  • Requisitos que evolucionan según feedback de usuarios
  • Permite entregar valor en cada sprint
  • GitHub Projects integrado con el repositorio del código
